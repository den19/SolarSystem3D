# Руководство программиста — Solar System V7

**Проект:** Solar System 3D (Unity URP)  
**Версия приложения:** 8.2.17 (Android `bundleVersionCode` 35)  
**Сцены сборки:** `Assets/_Scenes/MainMenu.unity`, `Assets/_Scenes/Level1.unity`  
**Скрипты:** `Assets/Scripts/` (~119 файлов)  
**Версия документа:** 2026-08-21  

Документ описывает архитектуру симуляции, режимы работы, особенности, известные недостатки и направления развития. Предназначен для разработчиков, поддерживающих и расширяющих приложение.

---

## 1. Обзор архитектуры

Приложение — образовательный 3D-симулятор Солнечной системы на **Unity** (UGUI, TextMeshPro, URP). Нет единого «тика» симуляции: вне Машины времени движение тел идёт в `Update()` через `Time.deltaTime` (`Time.timeScale` = `SpeedMultiplier`); в режиме Машины времени календарь и Kepler ведутся через `unscaledDeltaTime × SpeedMultiplier` при базе Phase A/B (50 или 1 год/с), а `Time.timeScale` остаётся 1 (подробности — §2.4).

```text
MainMenu ──► PauseAndResume (New / Continue)
                │
                ▼
             Level1
                │
                ▼
     SimulationViewBootstrap
        ├── SolarSystemScaleController
        ├── BodyOrbitSystemController
        ├── CometSystemController
        ├── OrbitLinesManager / BodyLabelManager / MinimapController
        ├── CleanViewController
        ├── ProbeSystemController (+ HUD, камеры, проекция)
        └── UI: SidePanel, TimeControl, ScaleBar, Share, Descriptions
                │
                ▼
     SimulationSessionRestorer / Autosave (PlayerPrefs)
```

Ключевые статические настройки (`*Settings`) хранятся в **PlayerPrefs** и поднимают события при изменении. UI-контроллеры подписываются на события и синхронизируют Toggle/Slider.

## 2. Механики симуляции

### 2.1. Орбиты планет и спутников

| Режим | Класс | Поведение |
|--------|--------|-----------|
| Круговые (по умолчанию) | `RotateAround` | Вращение вокруг центра с постоянной угловой скоростью (deg/s × `deltaTime`) |
| Эллиптические («Реальные орбиты») | `BodyOrbitController` | Фаза `phaseRad`, эксцентриситет и наклонение из каталога |

Переключение: `OrbitSettings.UseRealOrbits` → `BodyOrbitSystemController`.

Данные тел: `SolarSystemCatalog` — AU, радиусы (км), эксцентриситет, наклонение, орбиты спутников.

**Текущий набор тел**

- Звезда: Sun  
- Планеты: Mercury, Venus, Earth, Mars, Jupiter, Saturn, Uranus, Neptune
- Карликовые планеты: Pluto (гелиоцентрическая; Харон пока не добавлен)
- Спутники: Moon (Earth); Phobos, Deimos (Mars); Io, Europa, Ganymede, Callisto (Jupiter); Titan (Saturn); Triton (Neptune)
- Порядок навигации: … Uranus → Neptune → Triton → Pluto → [кометы по SMA]

### 2.2. Кометы

- Каталог: `CometCatalog` — 10 периодических комет (Encke … Howell) с `simPeriodSec`.  
- Система: `CometSystemController` создаёт иерархию под `CometsRoot`.  
- Движение: `CometOrbitController`; визуал: `CometVisualController` (стадии активности).  
- Описание: `CometDescriptionPanel`.

Реальные орбиты комет включаются только если **одновременно** включены «Реальные орбиты» и «Движение комет».

### 2.3. Масштабы представления

`ScaleMode` (`ScaleSettings`):

| Значение | Смысл |
|----------|--------|
| `Educational` (0) | Сжатая учебная схема: крупные тела, короткие орбиты |
| `TrueScale` (2) | Реальные отношения орбит; размеры тел мягко сжаты (`TrueScaleSizeExponent ≈ 0.4`) |

Устаревший режим `RealDistances` (1) удалён; при чтении PlayerPrefs мигрирует в Educational.

Применение: `SolarSystemScaleController` + `SolarSystemLayout`.

### 2.4. Управление симуляционным временем

#### Панель скорости (`SimulationTimeController`)

Статический контроллер паузы и множителя:

- Диапазон **0.25× … 256×** (кнопки ÷2 / ×2), значение в `SpeedMultiplier`.  
- Пауза **отдельно** от скорости: при паузе `Time.timeScale = 0`, множитель **не затирается**. Его можно менять на паузе; после Play симуляция идёт с актуальным `SpeedMultiplier`.  
- `Apply()`:
  - вне Машины времени → `Time.timeScale = SpeedMultiplier`;
  - в Машине времени (`SimulationClock.DrivesMotion`) → **`Time.timeScale = 1`** (панель ускоряет только календарь, не весь `deltaTime`);
  - при паузе → `0`.  
- `ForceSpeedOneX()` — принудительно `SpeedMultiplier = 1` и обновление UI (используется на рубежах TM).  
- UI: `SimulationTimeControlBar` на `MainScreenCanvas` (`TimeControlUiBootstrap` / `TimeControlSceneSetup`); portrait — центр низа, landscape — слева внизу; safe area.

#### Режим «Машина времени»

Классы: `TimeMachineSettings` (тумблер / PlayerPrefs), `SimulationClock` (календарь), `TimeMachineController` (тик + Kepler), `TimeMachineDateHud` (дата над ScaleBar).

**Включение:** только тумблер на боковой панели (дефолт выкл.). New принудительно выключает режим. Автостарта нет.

**Календарный проход:**

1. Старт: −100000-01-01 (`ResetToSweepStart`).  
2. Sweep до +100000.  
3. Мгновенный snap на текущее земное время **UTC+3**.  
4. Дальше фаза Live (бесконечность вперёд).

**Двухслойная модель темпа** (важно для рубежей):

| Слой | Что это | Где |
|------|---------|-----|
| База календаря | лет симуляции за 1 реальную секунду при панели 1× | `SimulationClock` (`PhaseAYearsPerSecond` / `PhaseBYearsPerSecond`, флаг `_useSlowSweepRate`) |
| Множитель панели | 0.25× … 256× | `SimulationTimeController.SpeedMultiplier` |

Итоговый темп:  
`years/s = GetYearsPerSecond() × SpeedMultiplier`,  
где `dt` в `TimeMachineController` = `unscaledDeltaTime × SpeedMultiplier`.

| Режим базы | База при 1× | Пример при ×256 |
|------------|-------------|-----------------|
| Phase A (до первого рубежа) | **50 лет/с** | 12 800 лет/с |
| Phase B / slow Sweep (после рубежа) | **1 год/с** | 256 лет/с |
| Live (после snap +100000) | **1 год/с** | 256 лет/с |

Почему одного сброса панели в 1× мало: при базе 50 лет/с и панели 1× Земля всё ещё делает ~50 оборотов/с — визуально «ускоренная» симуляция. Поэтому на рубежах сбрасывается **и панель, и база**.

**Рубежи автосброса** (каждый — один раз за проход; пороги задаются в `ResetSpeedMilestones` при старте TM):

1. **Год 0 (н.э.)** — continuous year `0.0` (HUD ≈ `0000-…`).  
2. **Текущая дата UTC+3** — полный continuous year «сейчас» (`DateTimeOffsetToContinuousYear`), не 1 января; на HUD должна совпасть `yyyy-MM-dd` «сегодня».

При пересечении рубежа (`SimulationClock.Tick`, split-tick):

1. Календарь **останавливается ровно на рубеже** (остаток большого прыжка на высокой скорости отбрасывается).  
2. `ForceSpeedOneX()` — панель → **1×**, UI обновляется.  
3. `_useSlowSweepRate = true` — база Sweep **50 лет/с → 1 год/с** до конца прохода (и для Live).  
4. Со следующего кадра движение Kepler идёт уже с медленной базой × текущий `SpeedMultiplier`.

После первого рубежа пользователь снова может поднять панель (×2 … ×256); темп считается от базы **1 год/с**. На втором рубеже снова принудительно 1× (база уже медленная).

Сброс рубежей и быстрой базы: `ResetToSweepStart` / `ResetSpeedMilestones` при новом включении TM.

**Движение тел в TM:** только `TimeMachineController` → `ApplyKeplerPhases` / `ApplyKeplerAngles` по `DaysSinceJ2000`. Инкрементальные `RotateAround` / `BodyOrbitController.Update` отключены (`PrepareForTimeMachine`). Kepler-периоды: `SolarSystemCatalog` / a^(3/2), аномалия — `KeplerOrbitMath`.

**Дата HUD:** `TimeMachineDateHud`, формат `yyyy-MM-dd` (BCE: `-YYYYY-MM-DD`). Длина года на HUD — 365/366 (високосные / пролептический григорианский), как у порога «сегодня», чтобы рубеж и надпись совпадали. Видна только при включённом TM и `ShowSimulationUi`.

**Солнце:** `SunCoronalVfxController.ActivityScale` растёт с календарным годом (`EvaluateSunActivityScale`).

**Пауза в TM:**

- `IsPaused` → тик календаря и Kepler не выполняются.  
- `SpeedMultiplier` сохраняется; правки на паузе учитываются после Play.  
- Pause/resume **не** вызывают `ForceSpeedOneX` и не возвращают базу Phase A.  
- После Play: `Apply()` + один apply позиций с текущим множителем.

Вне Машины времени почти вся симуляция (орбиты, кометы, showcase-камера, часть VFX) использует `Time.deltaTime` и следует `timeScale`. UI и жесты камеры — `unscaledDeltaTime` / `unscaledTime`.

### 2.7. Графика на смартфонах (URP Mobile vs PC)

Android/iPhone всегда используют quality **Mobile** → [`Assets/Settings/Mobile_RPAsset.asset`](Assets/Settings/Mobile_RPAsset.asset). Standalone — **PC** → `PC_RPAsset`.

| Параметр | Balanced (mobile default) | High (mobile) | PC |
|----------|---------------------------|---------------|-----|
| Render Scale | 0.8 | 1.0 | 1.0 |
| MSAA | off (1) | 2× | 2× |
| Shadow map | 1024 | 1024 | 4096 |
| Soft shadows / SSAO | нет | нет | да (PC renderer) |

**Effective High** включается только если Extra Graphics ON **и**:

- mode = `High`, или  
- mode = `Auto` и `SystemInfo.graphicsMemorySize >= 2048`.

Иначе — Balanced. Runtime: `MobileUrpQualityApplicator` (только Android/iOS).

**«Бомбическое» Солнце на устройстве**

1. Extra Graphics ON + Real Sun ON (side panel / defaults).  
2. Graphics quality: Auto (на флагмане) или High.  
3. Сфокусировать камеру на Солнце — granulation/sunspots/flicker/CME и усиленный bloom на close zoom (`SunCoronalVfxController`).  

### 2.8. Режим зонда (gravity slingshot)

**Статус:** целевая спецификация (source of truth). Расхождение Editor/APK с описанием → править код под документ. Не все edge cases проверены на устройстве (см. §5).

#### Сценарий пользователя (кратко)

1. На боковой панели включить **«Зонд (экспериментальный)»** (`SidePanelProbeLabel`) → появляется HUD прицеливания и (до первого запуска) coach-подсказки.  
2. Выбрать **тело старта** (фокус камеры на планете/комете).  
3. Выбрать **модель**, настроить Impulse / Heading, смотреть **ghost-траекторию** и превью слева.  
4. **Launch** → камера **Chase**, PIP-обзор включается, toast об успехе, coach больше не показывается.  
5. В полёте: телеметрия справа, опционально Burn / Postcard, переключение World / Chase / Cockpit.

#### Включение и жизненный цикл

| Событие | Что видит пользователь / что происходит |
|---------|-------------------------------------------|
| Тумблер **«Зонд (экспериментальный)»** (default **выкл**) | Режим доступен только вручную с боковой панели; ключ `SidePanelProbeLabel` |
| Включение | HUD с launch bar, телеметрия, превью модели; режим **прицеливания** |
| Выключение | Полёт прерывается, HUD скрывается, Main Camera восстанавливается |
| Новая симуляция | Зонд принудительно выкл. |
| Continue | Камера и время восстанавливаются; **полёт зонда не** — зонд не в сессии |
| Выход в меню | Активный полёт abort |
| Reset настроек | Все prefs зонда + coach сбрасываются (coach снова до первого Launch) |

#### Coach overlay (до первого Launch)

**Цель:** провести нового пользователя через 4 шага без чтения документации. Overlay и кнопка **?** на launch bar показываются **только при включённом** `UseProbe` (`SolarSystem_UseProbe = 1`); при выключенном тумблере coach не активен.

| № | Когда показывается (авто) | Заголовок (ключ) | Смысл для пользователя |
|---|---------------------------|------------------|------------------------|
| 1 | *(устаревший шаг — авто начинается с 2 при UseProbe)* | `ProbeCoachStep1Title` | — |
| 2 | Зонд вкл., **нет фокуса** на теле каталога | `ProbeCoachStep2Title` | Выбрать планету (удобно с Земли) |
| 3 | Есть фокус на теле, полёт **не** начат | `ProbeCoachStep3Title` | Модель, Impulse, Heading, ghost-траектория, телеметрия |
| 4 | То же, финальный шаг перед Launch | `ProbeCoachStep4Title` | Нажать «Запуск» на launch bar; камера перейдёт в Chase |

Тексты шагов: `ProbeCoachStep{N}Body` (N = 1…4). Индикатор **N/4** в карточке.

**Поведение overlay**

| Действие | Результат |
|----------|-----------|
| Авто-шаг | Следует таблице выше (шаги 2–4); обновляется при смене фокуса |
| **Назад** (`ProbeCoachBack`) | Предыдущий шаг (с шага 2) |
| **Пропустить** (`ProbeCoachSkip`) | Overlay скрывается **до конца сессии**; prefs **не** меняются |
| **Вперёд** (`ProbeCoachForward`) | Следующий шаг |
| **?** на launch bar | Открыть coach вручную с текущего авто-шага (видна только до первого Launch и только при `UseProbe`) |
| Успешный **Launch** | Overlay **навсегда** скрывается (`SolarSystem_ProbeCoachLaunchCompleted = 1`) |
| **?** после первого Launch | Toast `ProbeCoachHelpDone` («Подсказки уже пройдены») |
| Полёт активен | Overlay **не** показывается (не мешает управлению) |
| Reset настроек | Coach снова активен с шага 1 |

**Критерии приёмки (coach):** overlay виден при первом входе в режим; шаги 1→4 соответствуют состоянию UI; Skip не блокирует Launch; первый Launch навсегда отключает coach; Reset возвращает coach.

**Touch / raycast:** затемнение (dim) **не перехватывает** touch — `Image.raycastTarget = false` (`ProbeCoachOverlay`, узел `Dim`); launch bar, слайдеры Impulse/Heading и телеметрия HUD остаются кликабельны **под** полупрозрачным overlay. Карточка coach и её кнопки (`raycastTarget = true`) принимают touch только в своей области; подписи TMP на кнопках — `raycastTarget = false`.

**Editor vs APK:** в Editor coach часто уже скрыт (`SolarSystem_ProbeCoachLaunchCompleted = 1` после первого успешного Launch в прошлой сессии); сохранённый `SolarSystem_ProbeCameraMode = 0` (World) тоже может маскировать баг Chase. На **свежем APK** coach активен до первого Launch **при включённом UseProbe** — проверять: (1) dim не блокирует launch bar; (2) **Launch на launch bar** запускает полёт; (3) камера сразу переходит в Chase и зонд виден в кадре. Для повторной проверки coach — Reset настроек или удалить prefs.

Визуал: затемнение экрана (~55 %), карточка по центру (ширина до 760 px), шрифты title **30**, body **28**, кнопки **26**.

| Чекбоксы (Views, Custom) | **28×28** |
| Слайдеры Impulse / Heading | высота **36** |

**Заголовок телеметрии** (отдельная строка над телом):

| Часть | Ключ | Пример (RU) |
|-------|------|-------------|

## 3. Режимы работы и настройки

### 3.1. Поток сессии

| Режим | API | Поведение |
|--------|-----|-----------|
| New | `PauseAndResume.StartNewSimulation()` | Очистка снимка сессии; старт Level1 с дефолтами камеры/движения/времени; Time Machine выкл.; **зонд выкл.** (`SetUseProbe(false)`) |

## 4. Особенности реализации

1. **Нет физики орбит** — кинематическая интеграция угла/фазы, не N-body.  
2. **Двойная камерная модель** — Main Camera + набор detail-камер по телам; усложняет фокус и сессию.  
3. **Масштаб TrueScale** — компромисс: истинные отношения орбит, но размеры не 1:1 (иначе внутренние планеты исчезают).  
4. **TimeScale глобален** — ускорение влияет на всё, что использует `deltaTime` (включая showcase).  
5. **Scene-first UI** — панель, time bar, навбар живут на сцене; Editor menu `Solar System/Setup …` + runtime bootstrap как fallback.  
6. **Side panel orientation scale** — portrait ×2, landscape ×1.5 от baseline (`SimulationSidePanelController` / `SidePanelUiBootstrap`); см. §3.2.  
7. **Safe area** — `SafeAreaInsets` для навбара, side panel, time bar, CpuLoadMonitor, ScaleBar.  
8. **CpuLoadMonitor** в portrait поднимается над time bar (bottom-right), в landscape остаётся у нижнего правого края.  
9. **ScaleBar** — линейка расстояния на `MainScreenCanvas` (runtime через `ScaleBarController.EnsureOnCanvas`): portrait/landscape bottom-right **над CPU** (если CPU выкл — на его месте), не пересекается с minimap (левый низ) и time bar (центр/лево). Подпись в AU (`SolarSystemScaleController.AuToUnity` + `SolarSystemCatalog.AuKm`); при близком зуме — км. Tap открывает локализованную подсказку (ключи `ScaleBarAu*`). В clean view скрывается вместе с HUD.  
10. **Share** — скриншот + Android share; сообщения локализованы.  
11. **Mobile graphics tier** — High поднимает renderScale/MSAA только на устройстве; в Editor (PC quality) картинка изначально сильнее.  
12. **Зонд (gravity slingshot)** — restricted N-body test particle, отдельный HUD и PIP; не ломает `LookAtTarget` / сессию; спецификация — §2.8.

### 6.2. Геймификация

1. **Gravity slingshot** — реализовано; **полная спецификация — §2.8**. Кратко: тумблер «Зонд» (default off), restricted N-body, **14 моделей** (ScrollRect ◀/▶), PNG-портреты в карточке модели, Chase/Cockpit, PIP auto на Launch, телеметрия, циановая проекция. Дальнейшее: миссии / очки (не новый experimental mode).  
2. **Квиз по астрономии** — вопросы у тела («какая планета ближе к Солнцу?»), очки в `GameState.score`.  
3. **Миссии наблюдения** — «найди комету», «сфокусируйся на Энцеладе», таймер на обычной скорости.  
4. **Unlockables** — открытие описаний/скинов после правильных ответов.  
5. **Сравнение периодов** — челлендж: подобрать time scale так, чтобы Меркурий сделал N оборотов за время одного оборота Земли.  
6. **Достижения** — посетил все планеты, включил TrueScale, посмотрел комету в perihelion-визуале.  

Геймификацию держать опциональной (toggle), чтобы не ломать «чистый» образовательный режим.

### 6.3. Усиление образовательной составляющей

1. Карточки фактов: масса, период обращения, температура, число спутников — из расширенного каталога.  
2. Сравнение «если Солнце — мяч…» в Educational mode.  
3. Временна́я шкала: режим «Машина времени» (`SimulationClock` / `KeplerOrbitMath`) — см. §2.4: двухслойный темп (база × панель), рубежи года 0 и текущей даты UTC+3 (панель 1× + база 50→1 год/с), HUD, пауза.  
4. Аудиогид / короткий narrator tour по телам (PlanEn).  
5. Режим «учитель»: скрыть UI, оставить time bar + крупный заголовок тела.  
6. Схема затмений / фазы Луны (упрощённо).  
7. Связь единиц: AU ↔ км на линейке масштаба (`ScaleBarController`) и в описаниях; период ↔ земные сутки — в описаниях.  
8. Локализация описаний планет полностью во всех 7 языках (проверить полноту ключей).  

### 6.4. UI / UX

1. Единый design token set (цвета/отступы) вместо разрозненных констант в bootstrap.  
2. Иконки pause/play вместо текста «II» / «>».  
3. Coach зонда реализован (§2.8); опционально — подсказки для side panel / time bar вне режима зонда.  
4. Явное разделение «настройки симуляции» vs «настройки сессии» в меню Continue.  
5. Адаптив: избежать наложений (CpuLoadMonitor / ScaleBar над time bar, minimap слева) для описаний и toast.  
6. Accessibility: крупные hit-area, контраст, TalkBack/VoiceOver labels (ключи уже частично есть для time control).  
7. Плавный переход New/Continue с превью сохранённого тела.  
8. Редизайн About / Settings в одном визуальном языке с Level1 HUD.  

### 6.5. Оптимизации

| Область | Идея |
|---------|------|
| Камеры | Одна orbit-камера + сдвиг target вместо N detail cameras |
| Орбиты | LOD линий орбит; отключение update далёких спутников вне фокуса |
| Кометы | Frustum / distance culling хвостов; shared materials |
| UI | Отключить raycast на декоративных Image; пул toast |
| CPU | Batch/Job для фаз орбит при большом числе тел |
| Память | Атласы текстур планет; сжатие ASTC на Android |
| Загрузка | Addressables для описаний и редких тел |
| TimeScale | При очень высоких скоростях — fixed substeps или clamp delta, чтобы не «перескакивать» орбиту |
| Профилирование | Регулярный проход Profiler на mid-range Android (целевой FPS) |
| Сборка | IL2CPP, managed stripping, отключение неиспользуемых пакетов UI Samples в релизе |

## 7. Быстрый справочник PlayerPrefs
